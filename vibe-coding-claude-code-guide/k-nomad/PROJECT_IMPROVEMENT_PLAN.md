# K-NOMAD 프로젝트 개선 계획

## 전제

- 실제 기능 구현은 아직 진행하지 않는다.
- 데이터베이스는 사용하지 않고, 이후 구현 시 mock 데이터만 사용한다.
- 현재 단계에서는 홈페이지와 인증 페이지를 중심으로 필요한 개선 범위를 정리한다.
- 인증 페이지는 현재 프로젝트 기준으로 `login`, `register`를 포함한다.

---

## Phase1: 페이지 및 내비게이션 정리

### 1. 이번 단계에서 개선할 사항 오버뷰

홈페이지와 인증 페이지 외의 화면 진입 요소를 제거하고, 사용자가 실제로 이동할 수 있는 범위를 홈과 인증 흐름으로 제한한다. 내비게이션에서는 인증 및 프로필 관련 버튼만 유지하고, 도시 등록이나 상세 보기처럼 아직 구현하지 않을 기능으로 이어지는 버튼은 제거한다.

### 2. 수정/개선해야 하는 기능

- [v] 홈페이지 `/` 유지
- [v] 로그인 페이지 `/login` 유지
- [v] 회원가입 페이지 `/register` 유지
- [v] 홈페이지와 인증 페이지 외의 추가 페이지가 있다면 삭제
- [v] 헤더 내비게이션에서 인증/프로필 관련 버튼만 유지
- [v] 헤더의 `도시등록` 버튼 삭제
- [v] 도시 카드의 `상세` 버튼 삭제
- [v] 추천 카드 또는 랭킹 카드의 `자세히 보기` 버튼 삭제
- [v] 별도 기능 구현을 암시하는 CTA 버튼 정리

### 3. 작업 완료 후 검증 확인해야 하는 기능

- [v] `/` 접속 시 홈페이지가 정상 표시된다
- [v] `/login` 접속 시 로그인 페이지가 정상 표시된다
- [v] `/register` 접속 시 회원가입 페이지가 정상 표시된다
- [v] 헤더에는 브랜드와 인증/프로필 관련 버튼만 표시된다
- [v] 홈페이지에서 다른 페이지로 이동하는 불필요한 버튼이 보이지 않는다
- [v] 삭제 대상 버튼 제거 후 레이아웃이 깨지지 않는다

---

## Phase2: 필터 및 도시 카드 데이터 구조 변경

### 1. 이번 단계에서 개선할 사항 오버뷰

기존 별점 중심의 도시 평가 구조를 제거하고, 예산/지역/환경/최고 계절 기준으로 도시를 비교할 수 있도록 mock 데이터와 카드 표시 구조를 변경한다. TOP 추천 도시 표현은 제거하고, 모든 도시를 좋아요 순서로 보여주는 도시 리스트 중심 화면으로 정리한다.

### 2. 수정/개선해야 하는 기능

- [v] 별점 평점 데이터 제거
- [v] 별점 UI 및 별 아이콘 제거
- [v] 기존 `scores`, `tags` 중심 표시 제거
- [v] 도시 mock 데이터에 `예산` 값 추가
- [v] 도시 mock 데이터에 `지역` 값 추가
- [v] 도시 mock 데이터에 `환경` 값 추가
- [v] 도시 mock 데이터에 `최고 계절` 값 추가
- [v] 도시 mock 데이터에 `좋아요` 숫자 추가
- [v] 도시 mock 데이터에 `싫어요` 숫자 추가
- [v] 예산 필터를 `100만원 이하`, `100~200만원`, `200만원 이상`으로 변경
- [v] 지역 필터를 `전체`, `수도권`, `경상도`, `전라도`, `강원도`, `제주도`, `충청도`로 변경
- [v] 환경 필터를 `자연친화`, `도심선호`, `카페작업`, `코워킹 필수`로 변경
- [v] 최고 계절 필터를 `봄`, `여름`, `가을`, `겨울`로 추가
- [v] 도시 카드에 예산/지역/환경/최고 계절을 Key-Value 형태로 노출
- [v] `TOP 추천 도시`, `오늘의 노마드 랭킹` 등 랭킹성 제목을 `도시 리스트`로 변경
- [v] 모든 도시를 좋아요 수 기준 내림차순으로 나열
- [v] 각 도시별 mock 데이터에 필터 기준 요소가 최소 하나씩 포함되도록 수정

### 3. 작업 완료 후 검증 확인해야 하는 기능

- [v] 홈페이지에서 별점 평점이 표시되지 않는다
- [v] 홈페이지에서 별 아이콘이 표시되지 않는다
- [v] 필터 항목이 요청한 값으로 표시된다
- [v] 도시 카드에 예산/지역/환경/최고 계절이 Key-Value 형태로 표시된다
- [v] 모든 도시 데이터에 예산/지역/환경/최고 계절 값이 존재한다
- [v] 도시 리스트 제목이 `도시 리스트`로 표시된다
- [v] 도시가 좋아요 수 기준 내림차순으로 정렬된다
- [v] mock 데이터만으로 화면이 구성된다

---

## Phase3: 좋아요/싫어요 버튼 상태 처리

### 1. 이번 단계에서 개선할 사항 오버뷰

별점 평점을 좋아요/싫어요 버튼으로 대체한다. 데이터베이스 저장 없이 브라우저 상태만 사용해 버튼 선택 상태, 색상, 숫자 변경을 처리한다. 새로고침 시에는 mock 데이터의 기본 숫자로 돌아가는 방식으로 제한한다.

### 2. 수정/개선해야 하는 기능

- [v] 도시 카드에 좋아요 버튼 추가
- [v] 도시 카드에 싫어요 버튼 추가
- [v] 좋아요 버튼에 기본 좋아요 숫자 표시
- [v] 싫어요 버튼에 기본 싫어요 숫자 표시
- [v] 좋아요 클릭 시 버튼 활성 색상 적용
- [v] 좋아요 클릭 시 좋아요 숫자 증가
- [v] 좋아요 버튼을 다시 클릭하면 선택 해제 및 숫자 원복
- [v] 싫어요 클릭 시 버튼 활성 색상 적용
- [v] 싫어요 클릭 시 싫어요 숫자 증가
- [v] 싫어요 버튼을 다시 클릭하면 선택 해제 및 숫자 원복
- [v] 같은 도시 카드에서 좋아요와 싫어요가 동시에 활성화되지 않도록 처리
- [v] 좋아요 선택 후 싫어요 선택 시 좋아요 선택 및 숫자 원복
- [v] 싫어요 선택 후 좋아요 선택 시 싫어요 선택 및 숫자 원복
- [v] DB 저장, API 호출, 영구 저장 기능은 추가하지 않음

### 3. 작업 완료 후 검증 확인해야 하는 기능

- [v] 좋아요 버튼 클릭 시 색상과 숫자가 변경된다
- [v] 좋아요 버튼 재클릭 시 색상과 숫자가 원복된다
- [v] 싫어요 버튼 클릭 시 색상과 숫자가 변경된다
- [v] 싫어요 버튼 재클릭 시 색상과 숫자가 원복된다
- [v] 좋아요와 싫어요가 동시에 활성화되지 않는다
- [v] 새로고침 후 mock 데이터의 기본 좋아요/싫어요 숫자로 돌아간다
- [v] DB 또는 외부 API 호출 없이 동작한다
- [v] 린트와 빌드 검증이 통과한다
